## Изменения

1. [Проходы только по компонентам](../../SpaceBattle.SECS/SecsStore.cs) убирают
   создание native entity и обратное отображение ключа для движения снарядов,
   обломков и частиц. Плотное generation-aware отображение уже было в baseline:
   словарь не вызывался на каждой обычной строке SECS. Остальные четыре адаптера
   используют прежний native query через совместимый keyed fallback, без
   заявления о таком же ускорении отображения у них.
2. [Steering](../../SpaceBattle.Core/Battle.cs) лениво переиспользует Identity,
   Weapon, проверку цели и её положение внутри одной строки. Ранний выход docking
   и условные чтения тяжёлого оружия/перегрева сохранены. Точный коэффициент
   затухания хранится в [ограниченном кэше из 64 слотов](../../SpaceBattle.Core/DampingFactorCache.cs)
   по битам Damping и dt. Nonfinite обходят кэш; изменения параметров через ref
   видны сразу. Приближённого Exp нет.
3. [AI](../../SpaceBattle.Core/TacticalAi.cs) заимствует негeneric snapshot и
   лениво готовит упорядоченные индексы противников только для незаблокированного
   поиска. Максимум два O(N) прохода на фазу для обычных команд. Необычные команды
   сохраняют полный поиск. Ленивые DPS/health-инварианты используют исходный
   порядок float-операций. Snapshot не подменяет live-чтения позиции в steering.

Радиус поиска цели не ограничен, дальние достижимые цели не отсекаются, порядок
serial ties сохранён. Глобальный scoring остаётся потенциально O(S²). Ракеты не
перенесены в новый архетип/список: полезный missile-only short circuit сохранён.
Массовых accessor-кэшей, SIMD kernels, unsafe-индексации и blanket aggressive
атрибутов не добавлено.

SECS Span живёт только в query с запретом структурных изменений и disposal,
включая вложенные callbacks. Локальный Count ограничивает все колонки; ссылки
не удерживаются через мутации. Удаление всех JIT/AOT bounds checks не заявлено.
IL-тесты выбранных AI-методов подтверждают отсутствие List.get_Item и ldobj
целого AiShipSnapshot, но не исчезновение всех native-копий и Mono trampolines.

## Native

Windows 11, Ryzen 9 9900X, SDK 8.0.425/runtime 8.0.31, Release FullOpts;
tiering и ReadyToRun одинаково отключены у вариантов. Это Step без рендера,
не FPS и не проверка ARM. Seed 7331, 96 кораблей на команду, LightSwarm,
бесконечные подкрепления, замена carrier выключена. Low/nominal/high: churn
.5/1/2. Прогрев отдельного боя 2400 тиков, новый измеряемый бой 1-2400,
checkpoints через 600. По три независимых повтора, порядок стадий чередуется.
Сборки и измерения не пересекаются.

## Браузер и Scalar

Штатный Mono AOT остаётся на stable .NET 8, native-C -Oz,
AOT-bitcode/link -O2. Нет CoreCLR/R2R или fast-math. В проекте явно задан
WasmEnableSIMD=false: браузер не может выбрать fallback внутри уже отвергнутого
SIMD-модуля. Двойной loader не добавлен, поставка консервативно скалярная.
Desktop runtime может выбирать поддерживаемые System.Numerics инструкции;
DOTNET_EnableHWIntrinsic=0 проверяет его скалярный путь.

Браузерная таблица и дополнительные проверки дополняются после локальных
production-сравнений. Native-проценты нельзя считать выигрышем WASM.

## Воспроизведение и Ограничения

Новые сырые данные и идентичности исходников/сборок только в ignored
Benchmarks.Local/tmp: data-locality-20261012, data-locality-final-20261012,
locality-native-alternating-20261012, locality-browser-primary-20261012.
Это намеренно не ссылки на опубликованные исторические результаты.

[locality-study.ps1](locality-study.ps1) чередует native checkpoints реализации.
[summarize_locality.py](summarize_locality.py) отвергает разницу конфигурации,
checksum, игровых/AI-счётчиков и популяций до сравнения времени.
[Браузерный harness](../web/mono-compiler-study.mjs): свежие процессы,
отдельный прогрев/reset, точные тиковые состояния/checkpoints,
раздельные Step/export/frontend CPU. Frontend: Canvas submission, не GPU busy,
compositor cost или realtime FPS.

Снижение branch/cache misses не заявлено. WPT перечисляет PMCs, но текущий
токен не административный; существующие tracing-сессии не менялись.
[Методика Microsoft](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/recording-pmu-events)
не является измерением счётчиков в этом отчёте. Power/thermals, OS-кэши и чужие
процессы не контролируются. Битовая межплатформенная детерминированность и
непроверенные CPU/browser architectures не заявлены.
