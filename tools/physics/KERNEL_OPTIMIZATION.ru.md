# Структурная оптимизация circle-kernel

[Индекс исследований](../../docs/space-battle/RESEARCH.ru.md) | [Текущий отчёт](../../docs/space-battle/REPORT.ru.md) | [Сравнение с Aether](README.ru.md)

Сравниваются сохранённое текущее C#-ядро и оптимизация, не Aether. Старые результаты
и опубликованные отчёты не переписываются. Все новые сырые данные, исходники и DLL
сохраняются в новых ignored-каталогах `Benchmarks.Local/tmp`. Удалённых операций нет.

## Протокол

Сначала сохранить фактические dirty-исходники и baseline DLL. Собрать Release
`KernelBench.csproj`; `-p:StudyAssemblies=ABSOLUTE_DLL_DIRECTORY` позволяет использовать
сохранённый `SpaceBattle.Core.dll`, не пересобирая его. Архивируются SHA256 реальных DLL.
Текст исходников измерителя в момент запуска не доказывает происхождение старой DLL.

```powershell
python -B tools/physics/kernel_bench.py run --baseline BASELINE_KernelBench.dll --candidate CANDIDATE_KernelBench.dll --output Benchmarks.Local/tmp/NEW_PAIR --approved-timing-window --repeats 3 --frames 120 --sweeps 1024
```

Сборки и другие тяжёлые проверки должны закончиться до окна измерений. Чужие процессы
не останавливаются. Каждый повтор имеет новый процесс, отдельный прогрев и сброс
истории контактов; порядок вариантов чередуется. Последовательные тики не считаются
независимыми повторами. Основной показатель: медиана средних независимых повторов,
с их диапазоном. p95/p99 считаются по тикам внутри каждого повтора отдельно.

Учитываются все биты float положения, угла, скорости и вращения, поля контактов,
попадания/промахи и impact для кругов/прямоугольников. Нет заявления о совпадении
битов native и WASM. Native FullOpts микросцены (`DOTNET_TieredCompilation=0`), обычный
desktop и production Mono AOT измеряются раздельно. Step, export и rendering не смешиваются.

Отдельный `--instrumented` включает `CollectTimings` и `CollectDiagnostics`.
Эти времена предназначены для диагностики, не для оценки обычного throughput.
Счётчики сбрасываются в Step; последующие hit/spawn-запросы накапливаются до следующего
Step. Membership visits включают точный fallback вне окна. UniqueCandidates относятся
к каждому запросу. ContactPairs считает успешные проверки, NewConstraints уникальные
ограничения подшага. Rebuilds считает Seal, ContactBuilds логические проходы.

Микросцены содержат 198/774 тела, разреженные/плотные размещения, разные радиусы,
движущиеся/отключённые цели, большие координаты, owner exclusion и обе формы снаряда.
Быстрые сцены принудительно достигают восьми подшагов; отдельная плотная медленная
сцена использует один. Они не воспроизводят исторический замер Aether буквально.

## Сохранённая модель

Геометрия кругов, массы/инерции, трение, восстановление, интеграция, число подшагов
и итераций не меняются. Нормали и плечи исходного ограничения были фиксированными;
поэтому касательная и знаменатели масс вычисляются один раз теми же float/double
операциями. Скорости в точках контакта всегда читаются заново. Нет reciprocal,
fast-math, новой FMA, перестановки операций или warm starting.

Короткоживущий Span ограничений не переживает рост списка. Внутри velocity/position
проходов меняются только значения тел/импульсов; структурных вызовов нет.

Кэш потенциальных пар использует расширенные bounds. Перед повторным использованием
проверяется включение исходных outward-rounded bounds каждого тела в сохранённые.
Любой выход полностью перестраивает консервативный набор. Неразрешённые пары вновь
проверяются исходными tight AABB и точной circle-геометрией. Найденные пары удаляются
уплотнением без перестановки оставшихся. Новые контакты после коррекции обнаруживаются
в прежнем serial-порядке. При превышении бюджета включается полный точный путь, а не
усечение. `CacheContactCandidates=false` оставляет контрольный пересбор.

Метки индексируются compact body ID, не глобальным Serial эффектов. Generic spatial
index сохраняет duplicate-ID поведение. Контакты сортируются один раз по Serial;
CCD сохраняет numeric-порядок кандидатов и serial tie-break.

Размер ячейки остался 48 после трёхповторных сравнений с 24/32/64 на разных сценах:
общего победителя не оказалось. Margin 4 выбран после сравнения 2/4/8. Метаданные
окна 128x128 ограничены; 64 memberships на reserved bounds сохраняют отсутствие
аллокаций при допустимых перераспределениях. Pair-буфер ограничен 262144 парами
по умолчанию, до 2 MiB полезной нагрузки. Во время запросов/коррекций он не растёт.

Для CCD общие displacement и Sin/Cos готовятся только при первом подходящем теле.
Пустые запросы, только владелец или отключённые тела не вызывают эту арифметику.
Точная Minkowski-геометрия прямоугольника сохранена. Интервал пропускается только
когда его начало строго позже уже найденного попадания; равенство участвует в ties.
Первый интервал проверяется всегда, без лишнего деления нулевого начала.

## Ограничения

Неизменный граф не означает численной сходимости: тест демонстрирует изменение
скоростей после дополнительного полного прохода по прежнему связанному графу.
Основной вариант сохраняет все скоростные проходы.

Действительно плотные контакты остаются квадратичными по количеству пар. Grid этого
не отменяет. Большие fat bounds увеличивают кандидатов, выходы вызывают пересбор,
а точный fallback за пределами окна также может стать квадратичным. Бюджет ограничивает
память, не отменяя стоимость корректного полного fallback.

Process/managed memory включает входы и observer измерителя. Только отдельные
Step/hit allocation deltas характеризуют зарезервированный горячий путь. Весь игровой
Step со структурным созданием эффектов не объявляется allocation-free. Проверка
видео/скриншотов дополняет replay и геометрические тесты, но не заменяет их.
