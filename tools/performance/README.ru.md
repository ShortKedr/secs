# Диагностические инструменты Space Battle

Протокол ниже воспроизводит снимки **2026-10-11** (`6150700`, `c51390c`, `d853ae7`) с прежней физикой Aether. Это не инструкция профилирования текущего circle-kernel; для него используйте [HardwareStudy](../HardwareStudy/README.ru.md) и [физические инструменты](../physics/README.ru.md).

[Индекс исследований](../../docs/space-battle/RESEARCH.ru.md) | [Текущая кампания](../../docs/space-battle/REPORT.ru.md)

Эти инструменты исследуют затраты симуляции и фронтенда независимо от зафиксированных результатов сравнения пяти ECS. См. [исследование](../../docs/space-battle/PERFORMANCE_INVESTIGATION.ru.md).

Запускайте команды из корня репозитория. Храните архивы, сборки, кеши и результаты внутри `Benchmarks.Local/tmp/performance-study`. Не пересобирайте в канонический каталог `bin/Release` и не перезаписывайте результаты отчёта. [Экспериментальный патч](sweep-empty-space.patch) можно публиковать как исследовательский артефакт для воспроизведения, но не как исправление для production. Никогда не применяйте его к production-проекту и не развёртывайте вместе с production; применяйте его только к изолированной архивной копии для воспроизведения, как описано ниже.

## Нативное выполнение

Экспортируйте каждую ревизию локально через `git archive`, затем распакуйте её с помощью Windows `C:\Windows\System32\tar.exe` (стандартного инструмента ОС, а не приватного пути проекта). В исследовании использованы `before=6150700`, `tactics=c51390c`, `stats=d853ae7`. Экспорт архивов не изменяет рабочую копию Git или удалённое состояние.

```powershell
$root = (Get-Location).Path
$env:DOTNET_CLI_HOME = "$root/Benchmarks.Local/.dotnet"
$env:NUGET_PACKAGES = "$root/Benchmarks.Local/nuget-packages"
dotnet build tools/performance/SpaceBattle.Profile.csproj -c Release `
  --artifacts-path "$root/Benchmarks.Local/tmp/performance-study/native-stats" `
  "-p:StudySourceRoot=$root/Benchmarks.Local/tmp/performance-study/stats" `
  -p:NuGetAudit=false
dotnet "$root/Benchmarks.Local/tmp/performance-study/native-stats/bin/SpaceBattle.Profile/release/SpaceBattle.Profile.dll" `
  --revision d853ae7 --output "$root/Benchmarks.Local/tmp/performance-study/native-stats.json"
```

По умолчанию: три независимых повтора nominal/7331, 1,200 тиков, отчётные фазы по 600 тиков; отдельный прогрев на 1,200 тиков. `--ticks`, `--phase-ticks` и `--repeats` переопределяют количества. Измерения ядра исключают рендеринг, снимки состояния и телеметрию. Подсчёт, агрегация и контрольные суммы выполняются вне Step. Небольшие выделения памяти в измерительной обвязке всё же могут косвенно влиять на GC; сравнивайте эквивалентные обвязки.

## Браузер

Если они отсутствуют, установите локально существующий пакет `tools/web` и Chromium. Используйте закреплённые в проекте .NET SDK/wasm-tools и общий локальный кеш NuGet проекта. Публикуйте каждый архивный `SpaceBattle.Web.csproj` с `-c Release`, отдельным `--artifacts-path` и отдельным выходным каталогом. Не используйте `--Interpreter`.

Изолированной браузерной обвязке нужен следующий диагностический метод внутри каждого **архивного** `BattleBridge`:

```csharp
[JSExport]
public static double DiagnosticStage(int stage) => Current.LastStageMs[stage];
```

Он считывает существующие значения времени после Step; игровая логика не меняется. Раздавайте опубликованные каталоги `wwwroot` на трёх разных портах localhost с базовым путём HTML `/`. Все три полные AOT-сборки должны завершиться до начала измерений.

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD/Benchmarks.Local/tmp/playwright-browsers"
node tools/web/profile-revisions.mjs `
  --urls http://127.0.0.1:8030/,http://127.0.0.1:8031/,http://127.0.0.1:8032/ `
  --labels before,tactics,stats
node tools/web/summarize-performance.mjs Benchmarks.Local/tmp/performance-study
```

Настройки браузера по умолчанию: три независимых повтора для каждого URL, отдельный прогрев на 600 тиков, затем новый прогон тиков 1-1,200 с фазами по 600 тиков. Обвязка чередует порядок URL и отклоняет неожиданные количества тиков и ошибки выполнения. Она приостанавливает отрисовку/DOM, измеряет production-метод `Advance(1)` отдельно от диагностического чтения и записывает точные существующие длительности стадий, а также численность, счётчики и контрольные суммы. `--ticks`, `--phase-ticks`, `--repeats` и `--output` настраиваются.

Скрипт сводки проверяет повторяемость контрольных сумм, численности и игровых счётчиков внутри каждой ревизии/среды выполнения. Он не проверяет статистическую значимость и не сравнивает контрольные суммы native/WASM. Медианы рассчитываются по средним независимых прогонов, а не по минимумам отдельных тиков.

Для отдельной проверки плотной фазы с полным фронтендом:

```powershell
node tools/web/profile-web.mjs --url http://127.0.0.1:8032/ `
  --warmup-ticks 180 --output Benchmarks.Local/tmp/performance-study/web-live-1.json
```

Эта проверка измеряет тики 181-220, затем только экспорт и принудительное обновление UI в более поздних состояниях, после чего наблюдает пять секунд живого RAF. Эти интервалы нельзя вычитать друг из друга или считать одинаковыми нагрузками. Запустите проверку три раза с новыми страницами. Не запускайте сборки или другое профилирование одновременно.

## Эксперимент Sweep

Используйте свежую архивную копию `d853ae7`. Применяйте патч с явно заданным каталогом **только архивной копии**, никогда не с корнем рабочей копии:

```powershell
git apply --check --directory=Benchmarks.Local/tmp/performance-study/stats tools/performance/sweep-empty-space.patch
git apply --directory=Benchmarks.Local/tmp/performance-study/stats tools/performance/sweep-empty-space.patch
```

Публикуйте сборку в другой выходной каталог, сохраняя исходную опубликованную базовую сборку нетронутой. AOT-артефакты можно повторно использовать для того же архивного проекта. Соберите нативную обвязку с исходниками исправленной архивной копии в `native-sweep`, затем запустите её DLL с `--verify-sweep`. `SweepUnfiltered` существует только в этих экспериментальных исходниках для дифференциальной проверки; в браузере он не используется и может быть удалён при обрезке неиспользуемого кода.

Используйте браузерную обвязку с двумя URL, `--labels stats,sweep` и отдельным путём `--output`. Сравнивайте контрольные суммы фаз, численность и все игровые счётчики исходного и экспериментального вариантов, а не только время. Этот эксперимент не является интегрированным исправлением для production; нужны дополнительные начальные значения генератора и проверки граничных случаев физики.
