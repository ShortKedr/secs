# Нативные Адаптеры SpaceBattle

[Отчёт о бенчмарках](../docs/space-battle/REPORT.ru.md) |
[Обзор репозитория](../README.ru.md)

Библиотечный проект: `SpaceBattle.Adapters.csproj`. Публичные хранилища в
пространстве имён `SpaceBattle`: `LeoEcsLiteStore`, `LeoEcsClassicStore`,
`MorpehStore`, `StaticEcsStore`. Все реализуют `IEcsStore` через общий слой
идентификации `SpaceBattle.Core/NativeStore.cs`.

## Зависимости

Classic и Lite компилируют существующие исходники поставщиков как связанные
файлы, по аналогии с `Benchmarks.Local/Comparison.csproj`, без ссылки на его
исполняемый проект. Morpeh ссылается на существующий проект поставщика.
StaticEcs ссылается на `Benchmarks.Local/StaticLibrary.csproj` (1.2.01).
Версии поставщиков не изменяются.

## Контракт

- Компоненты и принадлежность к запросам хранятся только нативными фреймворками.
- `ForEach` использует нативные фильтры или итераторы запросов StaticEcs для всех трёх арностей.
- Аргументы компонентов и `Get<T>` являются действующими ссылками на нативное хранилище.
- `Get<T>` выбрасывает исключение при отсутствии компонента или устаревшем ключе; компоненты не добавляет.
- `Set<T>` добавляет или заменяет; `Remove<T>` и `Destroy` игнорируют устаревшие ключи.
- Логические ключи являются локальными для хранилища индексами повторно используемых слотов с независимыми поколениями.
  Слоты содержат сущности Classic, упакованные сущности Lite, сущности Morpeh
  или GID StaticEcs (включая поколение). Обратный словарь содержит только
  живые идентификаторы, а не историю уничтоженных сущностей. Размер хранения
  пропорционален пиковому числу живых сущностей, кроме слотов, выведенных из
  обращения при поколении `int.MaxValue`.
- Classic, Lite и Morpeh имеют закрытый маркер времени жизни: удаление последнего
  публичного компонента не уничтожает сущность неявно (в том числе при commit).
- Структурные операции, commit и освобождение ресурсов запрещены во время запросов.
  Запись через ref разрешена. Хранилища однопоточные.
- Вызывайте `Commit` после структурных изменений и перед запросами. Morpeh применяет
  здесь свои отложенные изменения; остальные реализации изменяются немедленно.
- Никогда не сохраняйте ссылки на компоненты между структурными операциями или после освобождения ресурсов.
- Детерминированные игровые серийные номера остаются данными компонентов и не зависят от нативных ID.

StaticEcs допускает ровно одно активное хранилище с фиксированным тегом мира.
Освободите старый экземпляр перед созданием нового. Все 25 структур из
`Components.cs` в Core регистрируются до инициализации. Дополнительные unmanaged-типы
нужно регистрировать в callback конструктора, например:

```csharp
using var store = new StaticEcsStore(r => r.Register<MyComponent>());
```

Диагностика сообщает число живых сущностей. Неизмеренные показатели архетипов,
чанков и байтов поставщиков неизвестны; их представление задаёт центральный отчёт.

## Сборка и Проверка

Запускайте из корня репозитория. Не начинайте параллельный restore, если другой
restore уже выполняется:

```powershell
$env:DOTNET_CLI_HOME = "$PWD/Benchmarks.Local/.dotnet"
$env:NUGET_PACKAGES = "$PWD/Benchmarks.Local/nuget-packages"
dotnet restore SpaceBattle.Adapters/SpaceBattle.Adapters.csproj
dotnet build SpaceBattle.Adapters/SpaceBattle.Adapters.csproj -c Release --no-restore -m:1
```

Зафиксированная Release-сборка адаптеров прошла без ошибок и предупреждений
после переноса общего слоя идентификации.

Библиотека предоставляет `AdapterValidation.RunAll()` для существующего
проверочного хоста; дополнительный исполняемый проект не вводится. Проверяются
все типы компонентов, время жизни пустой сущности, отсутствующие компоненты,
принадлежность к нативным запросам с 1/2/3 компонентами и запись через ref,
состояние процессора, удаление из кешированного запроса, запрет мутаций,
выход из запроса при исключении, отклонение устаревших ключей, повторное
использование слотов за 70,000 жизненных циклов (с переходом через переполнение
нативного 16-битного поколения), освобождение ресурсов, эксклюзивность StaticEcs,
дополнительная регистрация и восстановление после ошибки конструктора.
При ошибке выбрасывается исключение; при успехе возвращаются имена четырёх хранилищ.
`Validate(IEcsStore, int)` принимает владение пустым хранилищем и освобождает его
после проверки. `RunAll` печатает имя каждого фреймворка перед проверкой для
идентификации ошибок.

Зафиксированная проверка через существующий Release headless-хост с `--validate-adapters`:
все четыре адаптера прошли 70,000 итераций повторного использования и полный набор
вспомогательных проверок. Release-сборка хоста также прошла без ошибок и
предупреждений. Исходники headless-хоста не изменялись.
