# Урон По Слоям

Ревизия текущих исходников: **`layered-weapon-damage-v1`**. Desktop и production
Mono AOT WASM используют одни [C#-правила](../../SpaceBattle.Core/DamageRules.cs).
Это намеренное изменение игровой логики и старых траекторий/checksum, а не
перезапись исторических измерений или заявление об ускорении.

## Профили

| Оружие | Множитель щита | Множитель корпуса |
| --- | ---: | ---: |
| Plasma | 1.5 | 1 |
| MachineGun, Cannon, HeavyCannon | 1 | 1.5 |
| Missile | 1 | 1 |
| Столкновения и обломки | 1 | 1 |

Специализация 1.5 является **стартовой настройкой, не доказанным балансом**.
Базовый урон, темп стрельбы, ограничения нагрева, геометрия снарядов,
нейтральность к командам и иммунитет владельца не меняются. Снаряды турелей
используют фактический тип оружия своей пушки. Броня остаётся существующим
долевым уменьшением урона корпусу; новых классов брони нет.

Неизменяемые настройки находятся в `BattleConfig.Damage`. Коэффициенты должны
быть конечными и положительными. Единственное соответствие типа оружия профилю
находится в `DamageRules.ForWeapon`. Например:

```csharp
var config = new BattleConfig {
    Damage = new DamageSettings { Missile = new DamageProfile(1.2f, 1.1f) }
};
```

Существующий коэффициент нагрева от снятого плазмой щита остаётся 1.8 и в этом
изменении не является настройкой баланса. Для изменения специализации плазмы
используйте `new DamageSettings().Plasma with { ShieldMultiplier = 1.6f }`,
сохраняя поле нагрева.

## Один Удар

Для базового урона `D`, текущего щита `S`, множителя урона щиту `Ms` и множителя урона корпусу `Mh`:

1. На щит расходуется `min(D, S / Ms)` базового урона.
2. Со щита снимается потраченный базовый урон, умноженный на `Ms`.
3. В корпус проходит только оставшийся базовый урон.
4. Урон корпусу равен `остаток * Mh * (1 - броня)`.

Снятый щит ограничивается доступным щитом только для защиты от округления при
делении и обратном умножении float. Плазма добавляет `фактически снятый щит * 1.8`
нагрева; урон корпусу не нагревает цель. Урон ставит прежние состояния боя,
пробития щита и уничтожения в очередь. Старый `Damage(..., plasma: true, ...)`
использует плазменный профиль; false означает нейтральный урон. Все попадания
снарядов вызывают явный оружейный API `DamageWeapon`.

| Базовый урон 100, броня 0.2 | Щит до | Снятый щит | Урон корпусу | Нагрев плазмой |
| --- | ---: | ---: | ---: | ---: |
| Plasma | 75 | 75 | 40 | 135 |
| Кинетика | 75 | 75 | 30 | 0 |
| Missile | 75 | 75 | 20 | 0 |
| Plasma | 0 | 0 | 80 | 0 |
| Кинетика | 0 | 0 | 120 | 0 |

## Оценка AI

Этот раздел описывает первоначальную оценку слоёв v2. Текущие исходники используют
[layered-squads-v3](TACTICS_V3.ru.md): готовность, поэтапные первые попадания,
отдельные оценки подавления/потерь и подбор состава по полезности. Профили урона не менялись.

AI суммирует ожидаемый DPS каждого участвующего оружия отдельно для щита и
корпуса, учитывая профиль, точность/дальность и бюджет нагрева. Непрерывная
двухфазная оценка: `S / shieldDps + H / (hullDps * (1 - броня))`. Пустые слои
пропускаются; положительный слой без эффективного DPS считается недостижимым.
Общая эффективная прочность не делится на сумму сырого DPS смешанной группы.
Прежние время сближения/полёта, приоритет угрозы, фиксация цели и формирование групп сохранены.

Это приближение: оценка не симулирует дискретные залпы/избыточный урон,
будущую регенерацию щита, изменение нагрева, расписание прихода снарядов,
точный разворот/преграды турелей и несинхронный выбор целей. Оценка бортового DPS
сохраняет прежние пары Cannon/Plasma из каталога класса и независимый бюджет
охлаждения: произвольные внешние изменения, удаление и переподчинение пушек в этом
приближении не отражаются. Реальное попадание всегда использует профиль выпущенного
снаряда. Это эвристика выбора цели,
а не обещание фактического времени уничтожения.

## Проверка

Три отдельных native-процесса дали идентичные контролируемые сравнения по 24
строки. Каждый залп задаёт базовый урон 100, первый на тике 60, последующие через
60 тиков при 60 Гц. Корпус цели 1000, броня 0.25; меняется только начальный щит.
Смешанная пара задаёт 50 плазмы + 50 Cannon, состав из всех пяти типов по 20 на
тип. Ниже **секунды симуляции до уничтожения**, а не CPU-время.

| Состав | Щит 0 | Щит 750 | Щит 3000 |
| --- | ---: | ---: | ---: |
| MachineGun / Cannon / HeavyCannon | 9 | 17 | 39 |
| Plasma | 14 | 19 | 34 |
| Missile | 14 | 21 | 44 |
| Plasma затем Cannon | 11 | 17 | 35 |
| Cannon затем Plasma | 11 | 17 | 35 |
| Все пять | 11 | 18 | 38 |

Эти синтетические последовательные удары изолируют расчёт слоёв: без полёта,
промахов, регенерации, охлаждения, блокировки перегревом, AI и вторичных обломков.
Настоящие каталоги оружия не менялись. Плазма выигрывает на цели с большим
щитом, но при щите 750 кинетика всё ещё быстрее из-за преобладания работы по
корпусу. Это не проверка баланса флота. Сырые данные:
`Benchmarks.Local/tmp/weapon-damage-20261012/compositions-r1.json` до
`compositions-r3.json` (игнорируются, не публикуются).

Полная native-валидация и десять контрольных точек до тика 3000 прошли на всех
пяти адаптерах; итоговый checksum native-сценария `8C4682204BBAC537`. Проверки
урона/AI с принудительным скалярным режимом прошли. Прогретые пакеты прямых
вызовов `DamageWeapon` выделили ноль байт на пяти портах; это не утверждение
об аллокациях всего Step.

Собраны и запущены desktop Release на Windows x64 и production Mono AOT на
стабильном .NET 8.0.31. Chromium прошёл 11 проверок фактической AOT-формулы,
повторы со сбросом на трёх профилях, бой, управление и desktop/mobile рендер.
Desktop прошёл управление, счётчики, статистику и непустой рендер атласов на
тике 600. Неизменённый Playwright action client дошёл до тика 360 без ошибок.
Desktop, браузерные и мобильные кадры осмотрены, коллайдеры выключены.
Межплатформенное побитовое совпадение checksum и проверка других архитектур
CPU/браузеров не заявляются. Restore desktop предупредил о недоступности NuGet
vulnerability feed; сборка из кэша зависимостей прошла. Первые ошибки запуска/
localhost в sandbox и исправленный пропуск JS-поля ревизии сохранены в игнорируемых логах.

[Headless-проверки](../../SpaceBattle.Headless/Validation.cs) запускаются через
`--validate`, `--validate-adapters` и `--validate-ports`. Контролируемый
`--damage-study` сравнивает составы с одинаковым базовым DPS против целей со
щитом и без щита, не выдавая результат за доказательство баланса флота.
Новые данные сохраняются в игнорируемый `Benchmarks.Local/tmp`, без замены опубликованных бенчмарков.

Production [браузерные проверки](../../tools/web/check-web.mjs) проверяют
фактические результаты слоёв и ревизию в AOT, бой, повтор после сброса и рендер.
Ревизия экспортируется обоими фронтендами и новыми headless-отчётами.
