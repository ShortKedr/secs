# Протокол исследования и исправления iOS Web

Срез статуса: 2026-10-12. **Исправление НЕ проверено на настоящем iPhone.**
Это ограниченное исследование совместимости и восстановления, а не новый
этап оптимизации. Существующие отчёты и история измерений остаются без изменений.

## Доказательства и ограничения

- Исходный Jetsam-отчёт, переданный приватно: `iPhone17,3`, iOS `26.6.2`,
  страницы 16 КиБ, причина `vm-pageshortage`. Для WebContent записаны
  263.828 МиБ и максимум за время жизни 358.547 МиБ; для процесса GPU —
  69.422 МиБ. Системная wired-память — 5.361 ГиБ, свободная — 16.719 МиБ.
  Эти числа не устанавливают URL страницы и владельца wired-памяти.
  Нельзя складывать их в footprint страницы или помещать исходный лог
  в репозиторий.
- Свежий захват опубликованной версии получил 51 ресурс; все полученные
  записи boot-integrity совпали. Захваченный blob приложения `3595...`
  совпадает с локальным исходником в `2ca6446`; `74f1686` был HEAD документации
  на момент исследования. HTTP `max-age=600` допускает смешанный кеш в
  прошлом, но не доказывает его. Захват не устанавливает, что загрузила
  страница на телефоне при исходном сбое.
- Старый runtime создавал шесть стабильных Canvas-подложек атласов:
  37 743 264 байта RGBA, около 35.99 МиБ. Декодирование исходных PNG,
  временные readback-буферы и GPU-копии не учтены. Замена Canvas шестью
  прямыми PNG Image сохраняет тот же логический объём декодированных данных;
  **экономия 36 МиБ физической RAM не доказана**. Логические байты не равны
  резидентной памяти.
- Офлайн-анализ опубликованного WASM: 29 505 определённых функций,
  наибольшее тело 56 991 байт, одно тело больше 40 КиБ, Asyncify import/export
  отсутствуют. Локально до/после: 28 206/28 210 функций, тот же максимум
  56 991 байт; размер модуля изменился с 8 946 481 до 8 941 126 байт.
  Это инвентаризация кода, а не измерение памяти компилятора.
- [WebKit bug 304810](https://bugs.webkit.org/show_bug.cgi?id=304810) содержит
  пример с Asyncify и сообщения об аллокациях компилятора. Это не диагноз
  нашей страницы; отсутствие Asyncify import/export само по себе не исключает
  все проблемы компилятора WebKit. Padding функций и изменения компилятора
  не входят в это исправление.

## Необходимый объём исправления

- Генерировать шесть content-addressed PNG при сборке; использовать прямые
  Image вместо создания Canvas-атласов в runtime. Для ships с порогом -1 воспроизвести
  фактическую палитру и порог старого runtime; для остальных оставить порог
  32, сохранить все crops/pivots и существующее оформление desktop.
- Версионировать URL ресурсов через build identity. Отклонять несовпадение
  app/boot identity до запуска Mono; отклонять несовместимый browser/bridge
  contract.
- Перехватывать ошибки кадров/рендера, ставить паузу и показывать
  `diagnostics.error` в виде `{stage,message,...}` с видимыми load-state/Retry.
  Не продолжать ошибочный RAF-цикл и не повторять попытки бесконечно.
  Обрабатывать `contextlost`, где событие доступно; Retry перезагружает
  страницу и создаёт новый Mono, а не дублирующий экземпляр.
- Сделать resize идемпотентным и обновлять heap views при изменении памяти
  WASM. Общие правила симуляции, тики, определения флотов и счётчики не менять.

## Ограниченная проверка

Свежие страницы, конфигурация nominal, seed 7331.
`?diagnostics=<mode>&test=1` запускается на паузе без диагностического RAF-цикла.
Запросы только ручные, не более 120 тиков. Не нагружать телефон стресс-тестом
и не пытаться намеренно вызвать падение.

| Режим | Управляемая операция | Загрузка PNG |
|---|---|---|
| `simulation` | Step и export без рисования | Нет |
| `render` | Рисование замороженного tick 24 без Step | Шесть Image |
| `minimal` | Примитивы без изображений на замороженном tick 24, без Step | Нет |
| `normal` | Step, export и рисование | Шесть Image |

Прогреть отдельный бой одним sample, затем reset: simulation для страниц
simulation/minimal, normal для normal/render. Перед каждым окном render/minimal
сделать reset и подготовку
`diagnosticSample({mode:'simulation',ticks:24,renders:0})`; при рисовании
тик и checksum должны оставаться неизменными. Обычный sample использует
`ticks:1,renders:1`. Чистая simulation-страница отклоняет другие режимы sample.

Опциональный C# `DiagnosticStep` вызывает тот же Step без Snapshot; отдельно
показывать Step, export и отправку Canvas-команд из JS. Отправка Canvas-команд
не равна GPU time. Разделять WASM linear, managed, JS heap, Canvas backing и
decoded atlas memory; недоступная JS heap и GPU-память неизвестны, а не равны
нулю. Три свежие страницы на режим — независимые запуски; тики внутри окна
не независимы. Проверять неизменность image loads после двух reset,
`canvasResizes` при том же viewport, видимую ошибку, паузу и восстановление
через Retry/reload. Диагностическая инъекция ошибки не проверяет настоящий
RAF; такой случай проверяется отдельно без diagnostics query.

Команды ниже — протокол для main, а не свидетельство запуска. Выполнять из
корня репозитория с уже созданным сайтом; каждый раз заменять `<unique>` новым
идентификатором отчёта. Не перезаписывать предыдущие доказательства.

```powershell
node tools/web/run-ios-smoke.mjs --site Benchmarks.Local/tmp/ios-web-fix-20261012/after-site/wwwroot --browser webkit --ticks 24 --repeats 1 --faults --retry reload --raf-faults --output "Benchmarks.Local/tmp/ios-web-fix-20261012/smoke-webkit-24-<unique>.json"
node tools/web/run-ios-smoke.mjs --site Benchmarks.Local/tmp/ios-web-fix-20261012/after-site/wwwroot --browser webkit --ticks 60 --repeats 3 --output "Benchmarks.Local/tmp/ios-web-fix-20261012/diagnostics-webkit-60-<unique>.json"
```

Для Chromium использовать `--browser chromium`. Итоговая цель: три свежие
страницы на режим, окна до 60 тиков в каждом движке. Измерение старого приложения
до исправления main делает отдельно; нельзя считать, что оно поддерживает
новый diagnostic API. Desktop WebKit 26.5 — **не настоящий iOS**.

Проверенный desktop preview доступен только через loopback `http://127.0.0.1:8062/`;
телефон не может открыть loopback ПК. Для проверки устройства нужен отдельно
разрешённый HTTPS test host (WebCrypto integrity требует secure context).
URL ниже являются шаблонами, не опубликованными адресами:

```text
https://<authorized-test-host>/<site-base>/?diagnostics=simulation&test=1
https://<authorized-test-host>/<site-base>/?diagnostics=minimal&test=1
https://<authorized-test-host>/<site-base>/?diagnostics=render&test=1
https://<authorized-test-host>/<site-base>/?diagnostics=normal&test=1
```

Открывать по одному режиму и сохранять паузу. Через Safari Web Inspector
записывать состояние и выполнять только ограниченные samples. Для замороженных
режимов сначала подготовить tick 24, как выше. При ошибке, навигации/reload или
признаках давления на память остановиться; записать время и состояние вместо
многократных повторов.

## Приватные данные устройства

Для поиска владельца wired-памяти запросить существующие данные рядом с
инцидентом, с согласия владельца: приватный sysdiagnose, Instruments
VM/process/GPU traces, точное время и часовой пояс, URL/историю навигации,
версии приложения/build/Safari/iOS. Сопоставить state/network/console из Safari
Web Inspector с crash logs WebKit WebContent/GPU, watchdog-отчётами и
panic/respring-записями. Без логов или временных меток атрибуция остаётся
неизвестной. Не просить намеренно вызывать падение; исходные логи хранить
приватно вне Git, передавать только очищенные от личных данных сводки.

## Статус проверок

Production Mono AOT собрана и запущена. Полные Chromium-проверки проходят:
reload/recovery, три профиля, текстуры/эффекты, reset, zoom, follow и collider
debug. Оба движка проходят 12 свежих страниц (3 на режим), 32 сравнения состояний,
синтетические ошибки draw/context-loss и восстановление. Отдельные проверки
настоящего RAF, отсутствующего контекста и mixed-cache проходят в обоих движках.
Ошибки не выходят в pageerror. Неизменённый action-client дошёл до тика360 и
`599E654BA6B2097B`; просмотрены desktop/mobile WebKit и Chromium скриншоты боя.

Все три 600-тиковые checksum/счётчики совпадают с замороженной сборкой до правки:
nominal `B5D2A00D96AA1C33`, low `25A5FEBDF96C9F7D`, high `5E5B41175780CD28`.
Хеши 57 исходников симуляции и desktop-арт не менялись. Это не устанавливает
восстановление на iOS и побитовый детерминизм между разными движками.

Парные локальные сборки, nominal/7331, 390x844/DPR2: три свежие страницы на вариант,
чередование порядка. Один прогревочный тик отдельного боя, затем 60 одиночных
тиков; отдельно замороженный tick24, 12 прогревочных и 60 draw-вызовов. Медианы
средних страниц и min-max (ms); замеры внутри страницы не независимые повторы.

| Движок | Вариант | Step | Snapshot C# | Snapshot + interop/accept | Отправка JS Canvas |
|---|---|---|---|---|---|
| Chromium | До | 3.563 [3.545-3.868] | 0.433 [0.427-0.465] | 0.445 [0.440-0.468] | 4.388 [4.292-4.980] |
| Chromium | PNG | 3.672 [3.520-3.818] | 0.468 [0.468-0.498] | 0.452 [0.442-0.533] | 3.997 [3.798-4.218] |
| WebKit 26.5 | До | 4.667 [4.650-4.783] | 0.683 [0.583-0.817] | 0.700 [0.617-0.733] | 6.017 [5.267-6.117] |
| WebKit 26.5 | PNG | 4.800 [4.733-5.200] | 0.683 [0.667-0.750] | 0.683 [0.600-0.717] | 5.267 [5.200-5.700] |

Snapshot+interop включает capture; столбцы не складываются. Медианы рендера
уменьшились на 8.9%/12.5%, но диапазоны WebKit пересекаются; Step не ускорен,
короткие окна не доказывают устойчивый FPS телефона. Источники CANVAS6 -> IMG6,
логический RGBA остаётся 37743264 байта. У WebKit в сравнении tick24 максимальная
разница канала2; Chromium иначе уменьшает текстуры на маленьком масштабе
(17550/741000 сравниваемых пикселей отличаются больше delta8). Crops/pivots/
палитра/alpha policy сохранены, не точная фильтрация растра между типами источника
и backend.

Выигрыш памяти не подтверждён: синхронные парные пробы завершались с linear
95 -> 114 MiB в обоих движках и почти одинаковыми managed ~24.575 MiB.
Две отдельные инструментированные трассы grow/reset/export дали 95 MiB обоим
вариантам (ready79.125 MiB); рост идёт крупными шагами около20%. В диагностике
с дополнительными reset встречалось137 MiB. Это разные управляемые пути, не
физический footprint; причина дополнительного шага в парной пробе пока не
изолирована. Принудительный GC, уменьшение heap/численности или padding компилятора
для получения нужного результата не добавлялись. GPU/system/wired attribution
неизвестна; нужны данные настоящего устройства.
