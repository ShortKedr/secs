# Версии релизов SECS

SECS использует числовую версию по [Semantic Versioning](https://semver.org/lang/ru/)
для совместимости и название в кедровой теме для каждой линейки релизов.
Формат объявления релиза:

`SECS vMAJOR.MINOR.PATCH — Name · YYYY-MM-DD`

Дата — фактический день публикации в формате ISO. Она указывается в названии
релиза и примечаниях, но не входит в версию пакета или Git-тег. Числовая версия
определяет порядок обновлений; название и дата помогают людям. В коммитах и
отчётах о бенчмарках для воспроизводимости остаются точные Git-ревизии.

| Планируемая линейка | Название | Пример названия релиза |
| --- | --- | --- |
| `0.1.x` | Cone | `SECS v0.1.0 — Cone · YYYY-MM-DD` |
| `0.2.x` | Branch | `SECS v0.2.0 — Branch · YYYY-MM-DD` |
| `1.0.x` | Canopy | `SECS v1.0.0 — Canopy · YYYY-MM-DD` |

Это примеры именования, а не опубликованные релизы или обещанные даты. Если до
`1.0.0` понадобятся другие линейки `0.x`, каждая получит отдельное имя в той же
теме; Canopy оставляем для первого стабильного публичного API. Патчи сохраняют
название линейки, но получают собственную дату публикации, например
`SECS v0.1.1 — Cone · YYYY-MM-DD`.

## Иллюстрации релизов

Эта серия основана на существующем знаке ShortKedr ECS с белкой и кедровой
шишкой. Иллюстрации подготовлены для будущих заметок о релизах и сами по себе
не объявляют релиз. Фактические версию и дату при публикации добавляем текстом,
чтобы их можно было прочитать и найти поиском.

[Исходники и примечания к генерации иллюстраций](../branding/releases/README.md).

До `1.0.0` публичный API ещё развивается; несовместимые изменения нужно прямо
указывать в примечаниях к релизу. Начиная с `1.0.0`, MAJOR меняется при
несовместимых изменениях публичного API, MINOR — при совместимых новых
возможностях, PATCH — при совместимых исправлениях. При необходимости используем
обычные суффиксы предварительных версий, например `-rc.1`. Релиз библиотеки
получает Git-тег вида `secs-v0.1.0` и версию пакета `0.1.0`; название и дата
остаются в заголовке релиза. Одно лишь введение этих правил не создаёт релиз
и не назначает текущей сборке номер версии.
