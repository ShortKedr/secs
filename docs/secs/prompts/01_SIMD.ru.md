# Промпт реализации SIMD в SECS

Реализуй переносимый SIMD в основном проекте SECS из SECS.sln. Перед началом прочти `docs/secs/DEVELOPMENT_PLAN.ru.md` и `docs/secs/RELATED_CHANGES.ru.md`; их числовой контракт и границы задачи обязательны. Цель — готовый API числовых kernels с автоматическим SIMD и скалярным fallback для поддержанных операций.

Меняй SECS/, соответствующие SECS.Tests/, SECS.Benchmarks/ и docs/secs/. Сохрани существующие ForEach, Chunks и layout компонентов. Не включай SpaceBattle или миграцию потребителей в эту задачу. Сохрани чужие изменения. Не меняй файлы за пределами текущего проекта и удалённые состояния; не записывай в Miro.

1. Добавь типизированный IQueryChunkProcessor/ForEachChunk для запросов с 1–3 компонентами, используя имеющиеся QueryChunkView. Не предполагай, что unmanaged означает SIMD primitive, и не превращай поля component struct в SoA автоматически.
2. Добавь готовый AddInt32 kernel над непрерывными числовыми колонками, с явно заданным unchecked wraparound. Auto выбирает доступные API Vector128/Vector .NET 8 и fallback; Scalar принудительно использует эталон. Определи допустимое перекрытие входных и выходных диапазонов и не допускай молчаливого повреждения данных при частичном aliasing.
3. Используй невыровненные загрузки, корректный хвост, пустые и короткие диапазоны. Не читай и не пиши за Count. Не добавляй unsupported ISA без проверки доступности и fallback.
4. Когда доступен runner, векторизуй только физически непрерывные участки предоставленного логического диапазона. Не привязывай job ID, RNG, команды, события и редукции к Vector.Count. Общий chunk API может существовать отдельно, но его unrestricted pointers не считаются безопасным параллельным API.
5. Опиши путь расширения Fixed kernels через Raw после реализации числового контракта. Не обещай SIMD multiplication/division без корректного широкого промежуточного представления и доказанной parity. В первом выпуске неподдержанные операции исполняются скалярно.

Приёмка: bitwise равенство Scalar/Auto для пустых, коротких, точной ширины и tail диапазонов, отрицательных чисел, wraparound, нескольких чанков, capacities 1/63/256 и разрешённого aliasing. Проверь fallback отдельно при отключённых intrinsics в отдельном процессе. Тесты сравнивают значения, а не только факт отсутствия исключений.

Добавь BenchmarkDotNet сценарии с одинаковыми входами и проверкой результатов вне измеряемого участка; измерь полный query/kernel путь, dispatch, хвост и аллокации. Зафиксируй CPU/runtime. ARM64 и WASM включай в доказанные гарантии только после выполнения той же приёмки там.

Собери SECS, запусти релевантные тесты и проверь совместимость SECS.sln локально. Кеши инструментов и пакетов держи внутри проекта. В итоговом отчёте укажи supported kernels, fallback, замеры и непроверенные платформы. Обнови сопутствующие изменения с обоснованием каждого пути вне SECS/.
