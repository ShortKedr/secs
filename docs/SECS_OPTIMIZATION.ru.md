# Оптимизации среды выполнения SECS

[Руководство библиотеки](secs/README.ru.md) · [Карта документации](README.ru.md) · [Методология замеров](benchmarks/optimization-methodology.ru.md)

Статус: реализовано в текущем [CPU runtime](../SECS/World.cs). Этот документ описывает API и его стоимость. Измеренные ускорения относятся к связанным отчётам о бенчмарках; будущие SIMD, Fixed и scheduler описаны в отдельных [планах развития](README.ru.md#развитие-библиотеки).

## Существующий API

`World.Get<T>`, `Add<T>`, `Remove<T>`, `Set<T>` и запросы сохраняют
существующие способы вызова. Идентификаторы компонентов остаются локальными для мира;
обобщённый слот регистрации ускоряет их разрешение, не навязывая общий порядок регистрации компонентов.
Архетипы используют индексированный поиск столбцов. Рёбра структурных переходов кешируют
целевой архетип и план смещений и размеров исходных и целевых столбцов.

Каждый архетип отслеживает незаполненные чанки. При добавлении сущности сохранённая
свободная ёмкость используется повторно до выделения нового чанка. Удаление по-прежнему
перемещает последнюю сущность того же чанка на освобождённое место и обновляет её расположение.
Пустые чанки сохраняются для повторного использования, а не освобождаются немедленно;
объём хранилища зависит от исторического пика заполнения каждого архетипа, а не только
от текущего заполнения.

## Кешированный произвольный доступ

```csharp
var positions = world.GetAccessor<Position>();
ref var position = ref positions.Get(entity);
position.X += 1;
if (positions.TryGet(entity, out var copy)) { /* use the value copy */ }
```

Аксессор кеширует адреса компонентов и поколения сущностей. Создание,
миграция, удаление с перемещением последней сущности и уничтожение поддерживают его таблицу;
освобождение мира делает аксессор недействительным. Повторные запросы для одного компонента
используют одну общую таблицу. `Has` и `TryGet` отвергают уже недействительные поколения
и отсутствующие компоненты; `Get` в этих случаях выбрасывает исключение даже в Release.

Это явно включаемая возможность: обычные запросы и `World.Get<T>` не выделяют
таблицы адресов. В 64-битной среде выполнения каждый кешируемый компонент требует 12 байт
на выделенный слот ID (8-байтовый адрес плюс 4-байтовое поколение), без учёта заголовков массивов.
Ёмкость растёт геометрически и включает ID, у которых компонент отсутствует.
Структурные операции обновляют каждый зарегистрированный аксессор, поэтому регистрируйте
только компоненты, требующие частого произвольного доступа. Создание аксессора сканирует
существующие записи сущностей и не должно считаться бесплатной операцией.

`Entity` содержит только ID и поколение, но не идентификатор мира. Передавайте дескрипторы
только из мира-владельца: одинаковые ID и поколения в разных мирах могут совпасть.
Ни миры, ни аксессоры не являются потокобезопасными. Возвращённая `ref`-ссылка не должна
переживать структурное изменение или освобождение мира; кешируйте аксессор, а не ссылки на компоненты.

## Прямое создание

```csharp
var entity = world.CreateEntity(new Position { X = 1 }, new Velocity { X = 2 });
var factory = world.PrepareEntity<Position, Velocity>();
var another = factory.Create(new Position { X = 3 }, new Velocity { X = 4 });
var entities = new Entity[1000];
factory.CreateBatch(entities, new Position { X = 5 }, new Velocity { X = 6 });
```

Перегрузки `CreateEntity` принимают один, два или три unmanaged-компонента и помещают
сущность непосредственно в конечный архетип. Фабрика для двух компонентов кеширует
мир, архетип и идентификаторы компонентов. `World.CreateEntities` представляет собой
удобную пакетную перегрузку; подготовленная фабрика позволяет не повторять разрешение шаблона.
Пакетное создание инициализирует каждую выходную сущность одинаковыми переданными значениями.
Для разных значений используйте отдельные вызовы фабрики. Повторяющиеся типы компонентов
отклоняются до выделения сущности. Фабрики привязаны к миру и не могут создавать сущности
после его освобождения.

## Диагностика хранилища

`World.GetStorageStatistics()` сообщает количество сохранённых архетипов и чанков,
число живых сущностей, объём нативных буферов столбцов в байтах и объём полезных данных
массивов адресов и версий аксессоров в байтах. `NativeBytes` не включает управляемые
массивы сущностей и версий, метаданные и накладные расходы нативного аллокатора.
`AccessorBufferBytes` не включает заголовки управляемых массивов. Это диагностические
счётчики, а не полное измерение памяти процесса.

Парные замеры до и после оптимизации и отдельные замеры нового API описаны в
[методологии бенчмарков](benchmarks/optimization-methodology.ru.md). Исторические
графики пяти фреймворков остаются историческими; они не переименовываются незаметно
в замеры оптимизированной среды выполнения.
